- empty name keeps the old name: given a rename to blanks, expect the name is unchanged
- delete an empty page: given two pages, delete on the empty active one, expect the neighbour is active, with no dialog (AC-1)

- undo stays on its page: given edits on two pages, undo and redo on one (AC-3), expect only that page changes
- stack survives a switch: given an edit, a switch away and back (AC-3), expect undo reverts the edit, and a switch itself adds no entry

- viewport per page: given different scroll and zoom on two pages (AC-8), expect each is restored on switch; a new page opens at 0, 0 and zoom 1
- paste lands on the active page: given cut on one page and paste on another, expect the pasted elements have the target's pageId and the source has none left

- updateScene routes known elements: given onChange's elements written back with one element changed, expect every page keeps its elements

- hidden tab bar: given UIOptions pageTabs false, and zen mode, in turn, expect `page-tabs` isn't rendered
- host initialData and API: given initialData with two pages and activePageId (AC-13), expect api.getPages, getActivePageId and getAllPagesElementsIncludingDeleted report them; setActivePage, createPage, renamePage, movePage and deletePage work and take effect synchronously
- onChange carries all pages: given a host onChange on a two-page drawing, expect its elements include both pages, and appState has pages (FR-29)
- host that ignores pages: given a host using only initialData elements, updateScene and onChange (AC-13), expect one default page, elements have no pageId
- load replaces the drawing: given a multi-page file through app.loadFileToCanvas, expect pages and active page are the file's, and history is empty
- clear canvas keeps pages: given actionClearCanvas on page 2, expect page 1's elements and the page list are unchanged
