- Names: Element field `styleRanges?: readonly TextStyleRange[]` on ExcalidrawTextElement; type `TextStyleRange = Readonly<{ start: number; end: number; color?: string; highlight?: string }>` in packages/element/src/types.ts; AppState field `textEditorSelection: { elementId: string; start: number; end: number } | null`; actions `changeTextRangeColor` / `changeTextRangeHighlight` (exports actionChangeTextRangeColor / actionChangeTextRangeHighlight); en.json keys labels.textRangeColor = "Selection color", labels.textRangeHighlight = "Selection highlight". (not textRanges / richText field names; not a separate jotai store for the selection) — Requirements' working names, kept; Gate 0 put the selection in AppState.
- Where the range logic lives: All range maths, wrapped-line splitting and run layout (x offset and width per run) live in packages/element/src/textRanges.ts and are re-exported from @excalidraw/element; renderElement.ts and staticSvgScene.ts both call getStyledTextLines from it. textElement.ts, textWrapping.ts, textMeasurements.ts, mutateElement.ts and reconcile.ts are not edited. - No-ranges representation: No ranges = the styleRanges key is absent. Code that sets ranges goes through withStyleRanges(element, ranges), which returns a NEW element object (version and versionNonce bumped, as newElementWith does) carrying the normalized list, or the element without the key when the list is empty; it returns the same object when the normalized list is deep-equal to the current one. Readers treat undefined and [] the same (no ranges). (not styleRanges: [] or null as the empty value; not mutateElement in place) — Keeps existing snapshots byte-identical (C-3), and a new object identity is what invalidates elementWithCanvasCache (a WeakMap keyed by element), so no cache code changes.
- Editor-side shifting and selection tracking: Both live in packages/excalidraw/wysiwyg/textWysiwyg.tsx (App.text.ts, which owns handleTextWysiwyg, is not writable): editable.oninput shifts the latest scene element's ranges with shiftRangesForEdit before calling onChange, and textarea select/keyup/mouseup/input listeners write app.setState({ textEditorSelection }). handleSubmit sets it back to null. (not editing App.text.ts updateElement (outside the write contract); not wiring callbacks through App.tsx) — textWysiwyg already holds `app` and the textarea; App.text.ts's updateElement spreads the latest scene element, so ranges written to the scene before onChange are carried with the new text.
- Two extra colour pickers next to the stroke picker: ColorPicker gains an optional prop `popupId?: "textRangeColor" | "textRangeHighlight"`; when given it replaces `type` as the AppState.openPopup key (open state, toggles, close, memo comparison, data-openpopup). - Run layout and RTL: A styled line is laid out with absolute run positions: lineWidth = sum of run widths measured with getLineWidth in the element's font; lineStart = 0 (left), (element.width - lineWidth) / 2 (center), element.width - lineWidth (right). ### U02 — create `packages/element/src/textRanges.ts` (codegen)

Behaviour: Pure range model for styled text runs: normalize, apply a style, shift on edit, restore-validate, set on an element, and lay out styled runs per wrapped line for the canvas and SVG renderers.

Rules:
1. 1. Every function is pure: never mutate an input array or range object; return new arrays/objects (NFR-6).
2. 2. normalizeStyleRanges(ranges, textLength): drop entries whose start/end are not finite integers, or with no non-empty color and no non-empty highlight; clamp start/end to [0, textLength]; drop empty or inverted spans; resolve overlaps by painting entries in input order onto a per-boundary segment list so a later entry overrides the attributes it sets (sweep over sorted unique boundaries, not per character); sort by start; merge touching neighbours (a.end === b.start) whose color and highlight are both equal; never emit an attribute key whose value is undefined. Returns a new array (possibly empty).
3. 3. applyStyle(ranges, start, end, patch: { color?: string | null; highlight?: string | null }, textLength): if end <= start return the input array itself; otherwise split existing ranges at start and end, and for each sub-span in [start, end) set an attribute when the patch value is a string, delete it when null, keep it when the key is absent from the patch (a colour applied to highlighted text keeps the highlight); uncovered gaps inside [start, end) get only the patch's string attributes; then normalizeStyleRanges(result, textLength).
4. 4. shiftRangesForEdit(ranges, oldText, newText): if the texts are equal return the input array. Find common prefix length p and common suffix length s, with s capped so p + s <= min(oldText.length, newText.length). The edit replaces old [p, oldEnd = oldText.length - s) with ins = newText.length - p - s inserted chars; delta = ins - (oldEnd - p). Map a range's start: <= p stays, >= oldEnd moves by delta, inside the deleted span collapses to p. Map its end: < p stays, >= oldEnd moves by delta, inside the deleted span collapses to p, and end === p stays p only when start < p and the range does not extend past oldEnd. Net effect: insertion strictly inside a range (start < p < end, or a replacement whose deleted span lies strictly inside) extends it by ins; insertion exactly at a range's start or end leaves it unstyled (Q2); deleted chars are removed from covering ranges; drop ranges that end up empty; normalizeStyleRanges against newText.length.
5. 5. restoreStyleRanges(value: unknown, originalText: string): return undefined unless value is an array; keep entries that are non-null objects with finite integer start/end and color/highlight that are non-empty strings when present (copy only start, end, color, highlight); normalizeStyleRanges(kept, originalText.length); return undefined when the result is empty.
6. 6. getStyleRanges(element): return element.styleRanges when it is a non-empty array, else an empty frozen array constant; hasStyleRanges(element) is getStyleRanges(element).length > 0.
7. 7. withStyleRanges(element, ranges): normalize ranges against element.originalText.length; if the normalized list deep-equals getStyleRanges(element) return element; otherwise build `{ ...element }`, delete the styleRanges key, add it back only when the list is non-empty, then set version: element.version + 1, versionNonce: randomInteger(), updated: getUpdatedTimestamp() (both from @excalidraw/common).
8. 8. splitRangesIntoLines(originalText, wrappedText, ranges): returns StyledTextLine[] with one entry per wrappedText line (split on \n after normalizing \r\n). Align with two cursors: for each wrapped line, skip original characters that wrapping dropped (spaces or a single \n at a break) until the next original char equals the line's first char, then map each line char to its original offset by advancing both cursors (a mismatch skips the original char); after a line, step over one original \n if present. Group consecutive line chars whose original offsets fall in the same range (or none) into runs { text, color?, highlight? }; run texts concatenate exactly to the line; an empty line yields one run with text "". Never throw on misalignment: unmatched chars become unstyled. First normalize the input ranges against originalText.length, so stale out-of-bounds ranges are clamped.
9. 9. getStyledTextLines(element, env?: RenderEnvironment): return null when !hasStyleRanges(element). Otherwise split element.text into lines with splitRangesIntoLines(element.originalText, element.text, styleRanges); for each line measure each run with getLineWidth(run.text, getFontString(element), env); lineWidth = sum; lineStart = 0 for left, (element.width - lineWidth) / 2 for center, element.width - lineWidth for right; if isRTL(line text) place runs right-to-left in logical order starting at lineStart + lineWidth, else left-to-right from lineStart. Each laid-out run is { text, color?, highlight?, x, width }.
10. 10. Use getFontString and isRTL from @excalidraw/common, getLineWidth from ./textMeasurements, RenderEnvironment type from ./renderEnvironment; no DOM access.

Exports:
- `type StyledTextRun(): { text: string; color?: string; highlight?: string }`
- `type StyledTextLine(): { runs: StyledTextRun[] }`
- `type LaidOutTextRun(): StyledTextRun & { x: number; width: number }`
