# Requirements — feature-new — Pages (tabbed canvases in one drawing)

Run: `20261109-163637-feature-new-pages` · intent: `feature-new` · source: `intent_brief.md` (Gate 0 approved 2026-11-09)

## In scope

1. A page model in the editor library (`packages/element`, `packages/excalidraw`): a drawing holds an ordered
   list of one or more pages, each with a stable id and a name; exactly one page is active.
2. A tab bar in the editor UI to create, switch, rename, reorder and delete pages.
3. Per-page elements: only the active page's elements are rendered, hit-tested, selectable and editable.
4. Per-page viewport: each page keeps its own scroll and zoom, restored when switching back.
5. History scoped per page: undo/redo never changes elements of a page other than the active one.
6. Per-page export: image/clipboard/JSON-of-selection export of "the scene" covers the active page only.
7. Library insert and paste land on the active page.
8. Frames and bindings never span pages.
9. Search covers all pages; choosing a result on another page switches to that page.
10. File format: `serializeAsJSON` writes every page; restore reads it back. Legacy files (no page data) restore
    onto one default page. Older readers opening a new multi-page file may show every page's elements on one
    canvas; that is accepted (A-4).
11. `excalidraw-app` local autosave persists and restores every page.
12. `excalidraw-app` collaboration shares the page list and every page's elements live, including late joiners
    (`SCENE_INIT`), with no relay-server change.
13. Companion docs: `CHANGELOG.md` Unreleased → Features entry; `dev-docs` JSON schema and API pages.

## Out of scope

1. Collaboration relay server, Firestore security rules, CI workflows.
2. New npm dependencies; any `package.json` / `yarn.lock` change.
3. Moving or copying elements between pages; cross-page arrows, bindings or frames.
4. Multi-page export (one PDF/image of all pages).
5. Translations other than `locales/en.json`.
6. Per-page background colour or grid settings (drawing-wide unless the architect finds they must be per page
   and records why).
7. Excalidraw+ export (`ExcalidrawPlusIframeExport.tsx`) and share-link backend format, beyond what follows from
   `serializeAsJSON` carrying pages.
8. AI configs (`.claude/**`, `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`) and `.gitignore`.

## Functional requirements

### Page model and scene (`packages/element`, `packages/excalidraw` app state)

- **FR-1** A drawing has an ordered, non-empty list of pages `{ id, name }` and an active page id. The page-model
  storage choice (page id on every element vs separate element arrays per page) is made by the architect and
  recorded as an ADR in the change spec, weighing the brief's observations (collab/storage churn vs filtering
  cost in `Scene` and its consumers).
- **FR-2** Every consumer that reads "the scene's elements" for rendering, hit-testing, selection, frames,
  bindings and snapping sees only the active page's elements. Elements of other pages are preserved untouched.
- **FR-3** A new element (drawn, pasted, inserted from library, created by API `updateScene` without page data,
  generated by Mermaid/text-to-diagram) belongs to the active page.
- **FR-4** Adding page state to AppState follows the repo's four-touch convention: `types.ts`,
  `getDefaultAppState`, `APP_STATE_STORAGE_CONF`, `restore.ts`.

### Page operations (actions + tab bar)

- **FR-5** Create page: appends a new page with a unique id and a default localized name, and makes it active.
- **FR-6** Switch page: makes the chosen page active, clears selection/editing state, and restores that page's
  own viewport (scrollX, scrollY, zoom). A page never visited uses the default viewport.
- **FR-7** Rename page: sets a page's name from the tab bar (inline edit); empty/whitespace-only names are
  rejected (keep previous name).
- **FR-8** Reorder pages: changes the order of pages from the tab bar; the order persists through save/load.
- **FR-9** Delete page: removes the page and its elements. Deleting the last remaining page is not possible
  (action disabled / no-op). Deleting the active page activates a neighbouring page (the next, else the
  previous). A page deletion can be undone: undo brings back the page with its id, its name, its position in
  the page order and all its elements, and makes it active again (see FR-11).
- **FR-10** Page operations are implemented as actions registered via `register()`, named in the `ActionName`
  union, and re-exported from `actions/index.ts`. The tab bar is a component with a sibling `.scss`, rendered
  from `LayerUI`, with strings only in `locales/en.json`.

### History

- **FR-11** Undo/redo is scoped to the active page: an undo after switching pages never alters another page's
  elements. Deleting a page is undoable: undo restores the page (id, name, position in the order) and its
  elements, and redo deletes it again. Whether create/rename/reorder/switch are undoable is the architect's
  recorded decision; whichever is chosen, undo must never resurrect elements onto the wrong page.

### Export, clipboard, library, search

- **FR-12** Exporting through `exportScene` (`packages/excalidraw/scene/export.ts`, which replaced
  `exportToBlob` / `exportToSvg` on this base) — PNG, SVG and clipboard from the editor's export flow — contains
  only the active page's elements.
- **FR-13** Library insert and paste (`addElementsFromPasteOrLibrary`) assign inserted elements to the active page.
- **FR-14** Search (`SearchMenu`) finds matches on all pages; selecting a result on another page switches to that
  page and focuses the result.

### File format

- **FR-15** `serializeAsJSON` writes every page (id, name, order) and every page's elements in one file.
- **FR-16** `restoreElements` / `restoreAppState` (and `loadFromBlob`) read multi-page files back with every page,
  its name, its order and its elements intact.
- **FR-17** A legacy file (no page data) restores onto exactly one default page holding all its elements.
- **FR-18** Elements and pages with dangling references (an element whose page id is unknown, if that model is
  chosen; an active page id that does not exist) are repaired on restore (assigned to / fall back to a valid
  page), never dropped silently.

### excalidraw-app

- **FR-19** Local autosave (`LocalData`, `localStorage`) persists every page and the page list; reload restores
  them.
- **FR-20** Collaboration: the page list and elements of every page (not just the active one) are sent in
  `SCENE_INIT` and `SCENE_UPDATE` (or a new encrypted message subtype that the relay forwards unchanged), and
  reconciled on receipt. Create/rename/reorder/delete of a page and edits on a non-active page reach peers.
  Late joiners receive all pages. Firestore room persistence stores all pages.
- **FR-20a** The page list is merged one page at a time, not replaced as a whole: each page carries its own
  version (and version nonce, as elements do), and a received page wins over the local copy of the same page id
  by the same rule `data/reconcile.ts` applies to elements. A page deletion is a tombstone (`isDeleted`) with a
  bumped version, so it propagates and can be undone. Two peers creating pages at about the same time both keep
  both pages; the order of concurrently created pages is deterministic on every peer.
- **FR-21** A peer's active page and viewport are local: switching pages on one client does not switch peers.

### Companion docs

- **FR-22** `packages/excalidraw/CHANGELOG.md` gains an Unreleased → Features entry; `dev-docs` JSON schema page
  documents the page data; API docs document any new prop, `excalidrawAPI` method or `initialData` field.

## Non-functional requirements

- **NFR-1** Backward compatibility: every existing `.excalidraw` file, localStorage payload and collab room
  loads without data loss onto one default page.
- **NFR-2** Performance: switching pages and per-frame rendering on a single-page drawing must not regress;
  active-page filtering is cached/memoized (e.g. per `Scene` version), not recomputed per consumer per frame.
- **NFR-3** Type safety: `yarn test:typecheck` passes under the strict config; use `Merge<>`, immutable updates.
- **NFR-4** Conventions: jotai only via `editor-jotai` / `app-jotai`; `app.ownerDocument` / `app.ownerWindow`
  instead of globals; eslint import order with separate `import type` lines and no barrel imports.
- **NFR-5** No new dependencies; no relay-server, Firestore-rules or CI change.
- **NFR-6** Snapshot files change only through `yarn test:update`, never by hand.
- **NFR-7** Accessibility: tabs are keyboard-reachable buttons with accessible names; rename input has a label.

## PII inventory

| Field | Sensitivity | Protection |
|---|---|---|
| Page name | User content; may contain personal or confidential text | Treated exactly like element text: stored in the file/localStorage as today, sent over collab only inside the existing end-to-end-encrypted payload, persisted in Firestore only encrypted (as elements are). Never logged. |
| Page id | Random opaque id | None needed; generated with the existing random id utility. |

No new PII category is introduced; no data leaves the existing encryption boundary.

## Role matrix

| Role | Resource | Action |
|---|---|---|
| Editor user (local) | Pages of the open drawing | create, switch, rename, reorder, delete (not the last page) |
| Collaborator in a room | Pages of the shared drawing | same as editor user; changes propagate to all peers |
| Viewer (view mode / `viewModeEnabled`) | Pages | switch only (read); create/rename/reorder/delete hidden or disabled |
| Embedder (host app via props / `excalidrawAPI`) | Page data in `initialData` / `updateScene` / `getSceneElements` | read and supply pages per the API the architect defines |

## Acceptance criteria

- **AC-1** jsdom tests create, switch, rename and delete pages, and assert: only the active page's elements render
  and are selectable; undo stays on its page; exporting a page contains only its elements; a legacy file restores
  onto one page.
- **AC-2** `yarn test:typecheck`, `yarn test:code` and `yarn test:app --watch=false` all pass (baseline green:
  typecheck exit 0, lint exit 0, 149 files / 2632 passed, 47 skipped, 1 todo).
- **AC-3** Reordering pages from the tab bar changes their order, and the order survives save and load.
- **AC-4** Switching away and back restores each page's own scroll and zoom.
- **AC-5** A multi-page drawing round-trips through `serializeAsJSON` → `loadFromBlob`/restore with every page, its
  name, its order and its elements intact.
- **AC-6** The app's localStorage autosave restores every page after a reload.
- **AC-7** In collaboration, create/rename/reorder/delete of a page and an edit on a non-active page reach a peer; a
  test in `excalidraw-app/tests/` covers page list and elements reaching the peer; a late joiner (`SCENE_INIT`)
  receives all pages.
- **AC-8** Deleting the last remaining page is not possible; deleting the active page switches to a neighbour.
  Undoing a page deletion restores the page, its name, its position and its elements (FR-9, FR-11).
- **AC-9** Two peers that each create a page at about the same time both end up with both pages, in the same
  order on each peer (FR-20a).

## Assumptions

- **A-1** Viewport per page means `scrollX`, `scrollY` and `zoom`; other AppState (tool, styles, grid, theme,
  background) stays drawing-wide.
- **A-2** Default page name is localized via `en.json` (e.g. "Page 1"); default page id is a constant in
  `packages/common/src/constants.ts` so legacy restore is deterministic.
- **A-3** (revised at Gate 1) The page list in collaboration is merged per page, each page with its own version,
  as elements are (FR-20a) — not last-writer-wins on the whole list.
- **A-4** (Gate 1) Older versions of Excalidraw opening a multi-page file may show every page's elements on one
  canvas; that is accepted and needs no change.
