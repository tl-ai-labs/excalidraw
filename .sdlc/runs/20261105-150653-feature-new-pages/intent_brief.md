## Context

Seed description: "Add pages to a drawing: a tab bar to create, rename, reorder and delete pages, each with
its own elements and viewport, saved in one file and shared in collaboration."

From the brief, verbatim:

> Problem: an Excalidraw file holds one infinite canvas, so people who work on several related diagrams
> either crowd them onto one board or juggle many files and browser tabs. "Tabs in Excalidraw"
> (excalidraw/excalidraw#1543) has 86 votes since 2020.
>
> Before: the editor has a single canvas and no tab bar.
> After: a tab bar shows pages such as "SDK flow" and "Data pipeline", and clicking each tab switches the
> canvas to that page's own diagram and viewport.
>
> What it needs: packages/element (page membership on elements or per-page scenes, scene filtering),
> packages/excalidraw (app state for the active page, a tab bar UI, history scoped correctly, export and
> serialization, restore that puts legacy files on one default page, search across pages), and
> excalidraw-app collaboration and local storage. Rendering, hit-testing, selection, undo, frames, export,
> library insert and collaboration all assume one element list today. Choose between a page id on every
> element and separate element arrays, and keep file-format backward compatibility.

Discovery (`.sdlc/runs/20261105-095607-feature-new-pages/discovery.md`) confirms that a single flat element
list is assumed by Scene (`packages/element/src/Scene.ts`), Store/delta/History, `serializeAsJSON`/`restore`,
`reconcileElements`, the collab socket payloads (`excalidraw-app/collab/Portal.tsx`), Firebase storage
(`excalidraw-app/data/firebase.ts`) and localStorage (`excalidraw-app/data/LocalData.ts`). The file format is
at `VERSIONS.excalidraw = 2` (`packages/common/src/constants.ts`). `APP_STATE_STORAGE_CONF` is typed over
every AppState key.

## Goal

A drawing can hold several pages. A tab bar in the editor lets the user create, rename, reorder, delete and
switch pages. Each page has its own elements and its own viewport (scroll and zoom). Switching a tab shows
only that page's diagram. All pages are saved in one `.excalidraw` file and in the app's localStorage, and
page changes and per-page elements are shared in live collaboration and its saved room. Rendering,
hit-testing, selection, frames, undo/redo, export, library insert and search work correctly per page.
Search can find matches on other pages. Older single-page files load onto one default page. The architect
chooses between a page id on every element and separate element arrays per page, and records the
rationale.

Interview answers, from the brief:
- **What it does:** the seed description above.
- **What it needs:** the element/scene model (`packages/element`); editor app state, tab bar UI, history,
  export/serialization, restore and search (`packages/excalidraw`); collaboration (socket and Firebase) and
  local storage (`excalidraw-app`).
- **How it is tested:** jsdom integration tests that drive the editor, plus unit tests for the data model,
  serialization and restore. The repo's three gate commands must also pass (see below).

## Acceptance criteria

From the brief, verbatim:

> jsdom tests create, switch, rename and delete pages and assert that only the active page's elements
> render and are selectable, undo stays on its page, export of a page contains only its elements, and a
> legacy file restores onto one page; yarn test:typecheck, yarn test:code and yarn test:app pass.

Also implied by the seed description and the brief's "What it needs":
- Reordering pages from the tab bar is tested.
- Each page keeps its own viewport: switching away and back restores that page's scroll and zoom.
- One `.excalidraw` file round-trips all pages through save and load. A file written before this change
  (no pages) restores onto exactly one default page with every element intact.
- Collaboration: page create/rename/reorder/delete and per-page element changes reach a second client
  through the existing reconcile/broadcast path, and the Firebase-saved room keeps every page. This is
  covered by tests in `excalidraw-app/tests/`.
- localStorage keeps all pages across a reload.
- Search finds text on other pages and switches to the page of a chosen result.

## Non-goals

- Translating the new UI strings into non-English locales (Crowdin does this).
- Per-page library, per-page theme, or per-page collaborator permissions.
- Linking between pages (element links to another page) and exporting several pages into one PNG/SVG/PDF.
- Changes to excalidraw+ or the backend/storage services beyond the existing client-side Firebase and
  socket code.
- Version bumps, a release, or npm publishing of `@excalidraw/excalidraw`. A CHANGELOG entry is in scope.
