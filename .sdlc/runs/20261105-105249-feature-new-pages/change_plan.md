## Decisions

- Element page association and snapshot compatibility (`ExcalidrawElement.pageId`): Add optional `pageId?: string` to `_ExcalidrawElementBase`. Do not emit `pageId` on element literals when creating or restoring elements on `DEFAULT_PAGE_ID` (`"page-1"`) unless an explicit non-default `pageId` string is present; resolve missing or orphaned `pageId` values at runtime via `getElementPageId(element, pages)` returning the first page ID or `DEFAULT_PAGE_ID`. (not Always setting `pageId: "page-1"` on every created and restored element; not Storing per-page element arrays inside `AppState.pages`) — Omitting `pageId` when on the default first page preserves backward compatibility with legacy single-page `.excalidraw` files and keeps all existing single-page element snapshots unchanged while `Scene.insertElementsAtIndex` and `Scene.replaceAllElements` automatically stamp `pageId: this.activePageId` on newly created elements when `activePageId !== DEFAULT_PAGE_ID`.
- Page metadata model and viewport synchronization (`AppState.pages` and `AppState.activePageId`): Define `ExcalidrawPage = Readonly<{ id: string; name: string; scrollX: number; scrollY: number; zoom: Zoom }>` in `@excalidraw/element` and `@excalidraw/excalidraw`, default `AppState.pages` to `[{ id: DEFAULT_PAGE_ID, name: DEFAULT_PAGE_NAME, scrollX: 0, scrollY: 0, zoom: { value: 1 as NormalizedZoomValue } }]` and `AppState.activePageId` to `DEFAULT_PAGE_ID`, configure both `pages` and `activePageId` with `{ browser: true, export: true, server: true }` in `APP_STATE_STORAGE_CONF`, and sync top-level `scrollX`, `scrollY`, and `zoom` into the outgoing page entry and out of the incoming page entry whenever switching pages or updating viewport. (not Replacing top-level `AppState.scrollX`, `AppState.scrollY`, and `AppState.zoom` with page-only fields; not Keeping page viewports in component-local React state outside `AppState`) — Keeping top-level `scrollX`, `scrollY`, and `zoom` mirrored with the active page's entry in `AppState.pages` and marking `pages` and `activePageId` as `server: true` allows all existing renderer, viewport, local autosave (`FR-17`), `.excalidraw` JSON files (`FR-14`), and `#json=` share links (`FR-18`, `AC-10`) to round-trip pages and `activePageId`.
- Active-page filtering in `Scene` vs full-document access and `componentDidUpdate` render-count preservation: `Scene` tracks `activePageId` and `pageIds` via `scene.setActivePage(activePageId, pageIds)`, and `App.componentDidUpdate` calls `this.scene.setActivePage` and `this.syncPageHistoryStacks` only when `activePageId` or the page id list changed from `prevState`. (not Calling `this.scene.setActivePage` unconditionally on every `componentDidUpdate` when `activePageId` and `pages` ids did not change) — Guarding `scene.setActivePage` and `syncPageHistoryStacks` at `App.tsx:4521-4525` preserves `Scene.getSelectedElements` cache identity on mount so `dragCreate` and `selection` render counts match HEAD (`NFR-3`).
- History and undo/redo tracking for page mutations and page-scoped element edits: Include `pages` (but not `activePageId`) in `ObservedStandaloneAppState` (`packages/element/src/store.ts` and `packages/excalidraw/types.ts`) and `AppStateDelta` (`packages/element/src/delta.ts`), never switch `activePageId` in `StoreDelta.applyTo`, maintain per-page undo/redo stacks in `App` (swapping `this.history.undoStack` and `this.history.redoStack` in-place when `activePageId` changes), and schedule `CaptureUpdateAction.NEVER` in `addPage` so the page-list change does not land on the newly created page's undo stack and a new page starts with an empty undo stack. (not Recording `activePageId` in `ObservedStandaloneAppState` or switching `activePageId` in `StoreDelta.applyTo` on undo/redo; not Calling `this.store.scheduleCapture()` after `syncPageHistoryStacks` in `addPage`, which pushes the `pages` delta onto the newly created page's undo stack) — Satisfies `FR-6` and `AC-5`: undo and redo never switch pages, page switches (`activePageId`) are not recorded in history, a newly created page starts with an empty undo stack, and undoing or redoing on a page applies only to that page's changes without mutating inactive pages.
- UI control gating and placement for `PageBar`: Use a single opt-in switch `UIOptions.canvasActions.pages: boolean` with `pages: false` in `DEFAULT_UI_OPTIONS.canvasActions` (since `AppProps["UIOptions"]["canvasActions"]` is `Required<CanvasActions>`, keeping it off by default in `@excalidraw/excalidraw`, with no `?? true` fallback and no separate `pagesUIEnabled` / `UIConfig.enabled.pages` flag), gate `PageBar` on `Boolean(app.props.UIOptions.canvasActions.pages) && !appState.zenModeEnabled && (app.isInteractionEnabled() || app.isNavigationEnabled())`, enable `UIOptions.canvasActions.pages: true` in `excalidraw-app/App.tsx`, render `PageBar` in both desktop `Footer` and mobile `MobileMenu`, and in `viewModeEnabled` allow switching tabs while hiding `+`, rename, reorder, and delete controls. (not Enabling `pages: true` in `DEFAULT_UI_OPTIONS.canvasActions` or adding a separate `UIConfig.enabled.pages` / `pagesUIEnabled` flag; not Hiding `PageBar` completely in `viewModeEnabled`) — Satisfies `FR-7` and `AC-1` with a single opt-in switch `UIOptions.canvasActions.pages` that defaults to `false` in `DEFAULT_UI_OPTIONS.canvasActions` (`@excalidraw/excalidraw`) and is enabled in `excalidraw-app/App.tsx`.
- Multi-page collaboration synchronization and backward-compatible Firebase room storage: Extend `WS_SUBTYPES.INIT` and `WS_SUBTYPES.UPDATE` payloads with optional `pages?: readonly ExcalidrawPage[]` and `WS_SUBTYPES.MOUSE_LOCATION` and `WS_SUBTYPES.USER_VISIBLE_SCENE_BOUNDS` payloads (plus `Collaborator`) with optional `pageId?: string`; accept an optional third argument `elements?: readonly ExcalidrawElement[]` in `reconcilePages(localPages, remotePages, elements)` so local pages missing from `remotePages` that still have non-deleted elements on them are preserved (`AC-12`), and pass `reconciledElements` / `elements` at all `Collab.tsx` and `firebase.ts` call sites; in `excalidraw-app/data/firebase.ts`, always encrypt a JSON array inside `FirebaseStoredScene.ciphertext` (encoding `elements` unchanged when `pages` is the single default page, and appending a sentinel `{ id: "__excalidraw_pages__", type: "selection", pages }` entry to the array when custom or multiple pages exist, which `decryptElements` extracts and removes). (not Dropping local pages missing from `remotePages` in `reconcilePages` even when non-deleted elements are still on them; not Encrypting a non-array `{ elements, pages }` object as the root payload in `FirebaseStoredScene.ciphertext`, which breaks older clients calling `restoreElements` -> `arrayToMap` -> `items.reduce`) — Preserving local pages that still have non-deleted elements in `reconcilePages` ensures a page created before its broadcast is not dropped (`AC-12`), and keeping `FirebaseStoredScene.ciphertext` as a JSON array ensures backward-compatible E2E-encrypted Firebase room storage (`FR-19`, `NFR-1`, `NFR-4`).
