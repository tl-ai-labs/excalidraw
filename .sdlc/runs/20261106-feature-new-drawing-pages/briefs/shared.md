## Conventions

- TypeScript strict, ESM, React 19 function components; prettier via @excalidraw/prettier-config (80 cols, double quotes, trailing commas); eslint --max-warnings=0 must pass.
- Import order (eslint import/order): external libs, blank line, @excalidraw/common, blank line, @excalidraw/element (one import statement per line group is fine), blank line, relative imports, then `import type` statements last; use separate `import type` statements (consistent-type-imports).
- Packages import each other only through aliases (@excalidraw/common, @excalidraw/element, @excalidraw/element/types, @excalidraw/excalidraw/...); packages/element may import from @excalidraw/excalidraw/types with `import type` only.
- Never import jotai directly; never import excalidraw-app code from packages/*.
- DOM access goes through app.ownerDocument / app.ownerWindow, never the globals, in packages/excalidraw (AGENTS.md); prefer Merge<Base, Overrides> from @excalidraw/common/utility-types over Omit<> & {}.
- Elements are mutated only through newElementWith / mutateElement / scene.mutateElement (which bump version); the single exception is assignElementToPage on an element that is not yet in the scene.
- All new UI strings live in packages/excalidraw/locales/en.json under the `pages` namespace and are read with t("pages.x") from ../i18n (or ../../i18n); translation keys are type-checked, so a key used must exist in en.json.
- Components: PascalCase .tsx with a sibling .scss imported as `import "./X.scss";`, clsx for class names, BEM-like class names, theme CSS variables (var(--color-primary), var(--button-hover-bg), var(--color-on-surface), var(--island-bg-color), var(--default-border-color), var(--text-primary-color)) and `.excalidraw.theme--dark` for dark overrides; set Component.displayName.
- Actions are created with register({...}) from ./register, named in the ActionName union of actions/types.ts and re-exported from actions/index.ts; perform returns { appState, elements?, captureUpdate }.
- Tests: Vitest globals (describe/it/expect), `vi` imported from "vitest", jsdom; render/act/waitFor/fireEvent/GlobalTestState from tests/test-utils, API/Keyboard/Pointer/UI from tests/helpers; `const { h } = window;` exposes h.app, h.state, h.elements, h.history; assert with expect(...).toBe/toEqual/toMatchObject; no snapshot assertions in new tests.
- Snapshot files (__snapshots__/*.snap) are never typed by hand; they are regenerated by the tooling units that run vitest --update.

## Decisions

- Element page membership (FR-2 ADR): An optional `pageId?: string` on every element (_ExcalidrawElementBase); an absent pageId means the page DEFAULT_PAGE_ID ("default"). The Scene keeps its single ordered, fractionally indexed array of all pages' elements; a page's z-order is the relative order of its elements in that array. (not separate per-page element arrays (would split the Scene, fractional indices, Store snapshots/deltas and collab reconciliation into per-page structures, and break every API that hands over one elements array); not a required pageId (every legacy file, test fixture and host-built element would need it, and every element snapshot would churn)) — pageId is just another element property: Store/History deltas, collab reconciliation by id/version, fractional indices and restore() keep working unchanged, old readers keep the unknown field, and legacy elements land on the default page with no migration.
- Default page id and legacy files (FR-24): DEFAULT_PAGE_ID = "default" exported from packages/element/src/pages.ts; getDefaultPages() returns one page {id: "default", name: "Page 1", index: "a0", version: 1, versionNonce: 0, isDeleted: false}; elements on the default page carry no pageId key at all (assignElementToPage deletes the key rather than setting it). — Legacy files and existing tests need no stamping and produce no snapshot churn; every client derives the same default page id deterministically.
- Page record shape and order (FR-1): DrawingPage = { id: string; name: string; index: string (fractional key); version: number; versionNonce: number; isDeleted: boolean }. AppState.pages holds every page record including deleted tombstones; the tab order is getVisiblePages(pages): non-deleted pages sorted by index, ties by id. (not a plain ordered array of {id, name} (concurrent add/rename/delete from two collaborators could only be resolved last-writer-wins for the whole list)) — Per-page version records merge like elements (reconcilePages), so concurrent page edits by collaborators survive; fractional keys make reorder a one-record change.
- Per-page viewport storage (FR-8): AppState.pageViewports: Record<pageId, {scrollX, scrollY, zoom: number}> holds the saved viewport of pages; the active page uses the live scrollX/scrollY/zoom. Switching saves the live viewport under the page being left and restores the target's entry (or scrollX 0, scrollY 0, zoom 1). serializeAsJSON folds the live viewport into pageViewports[activePageId] before writing a local file. — Keeps the existing scroll/zoom state and every renderer untouched while making the per-page viewport part of the file; pageViewports is not sent to collaborators (server: false).
- AppState storage flags (FR-7): pages {browser: true, export: true, server: true}; activePageId {browser: true, export: true, server: true}; pageViewports {browser: true, export: true, server: false}. — Pages and the active page are saved to the browser and to files and share links; the viewport map stays local and in files.
- Scene filtering (FR-3, NFR-3): Scene gains activePageId; getNonDeletedElements(), getNonDeletedElementsMap() and getNonDeletedFramesLikes() return the active page only, computed in replaceAllElements and setActivePageId (cached, invalidated with the scene nonce); getElementsIncludingDeleted()/getElementsMapIncludingDeleted()/getElement() keep returning every page; new getNonDeletedElementsAllPages() returns every page's non-deleted elements. — The ~70 existing consumers of getNonDeletedElements (renderer, hit-testing, selection, snapping, binding, frames, fonts) become page-scoped with no edits and no extra pass per pointer move.
- Keeping the scene in step with AppState.activePageId: App.render() calls scene.setActivePageId(state.activePageId) when they differ; setActivePageId recomputes the caches and the nonce without firing onUpdate callbacks (safe during render). App.componentDidUpdate tells History the active page, reloads scene fonts on change, and switches to the first visible page when the active page is no longer visible (deleted remotely or via updateScene). — One place covers page switches from actions, updateScene from hosts, tab-sync and collaboration.
- Where new elements get the active page (FR-4, FR-27): Scene.insertElementsAtIndex stamps the scene's active page on elements not yet in the scene (all app.insertNewElement(s) paths, text, bucket fill, flowchart); App.addElementsFromPasteOrLibrary stamps the duplicated elements (paste, library, onInsertElements, mermaid/charts); the two actions that build elements themselves pass a pageId to the constructor (actionBoundText: the text's page; wrapSelectionInFrame: appState.activePageId). _newElementBase keeps an incoming pageId (omitting the key for DEFAULT_PAGE_ID), so element-type conversion keeps the page; duplicates copy the original's pageId. syncActionResult never re-stamps, so a loaded multi-page file keeps its pages. — Clipboard and library data may carry any pageId; stamping at insertion is the only place that knows the active page, and NEVER-captured results (scene init, undo/redo, remote) must keep their pages.
- Undo/redo scope (FR-21, FR-22 ADR): History keeps one undo and one redo stack per page id (Map); undoStack/redoStack getters return the active page's arrays; App calls history.setActivePage(id) when the active page changes, which emits HistoryChangedEvent. activePageId and pages are not part of the observed app state, so switching is never an undo step and undo never switches page. — Every element change happens on the active page, so tagging by the page active at record time scopes undo exactly to that page without touching Store or delta code.
- Page-structure changes and history (FR-14 ADR): addPage, renamePage, movePage(Left/Right), deletePage and switchPage return captureUpdate CaptureUpdateAction.NEVER: they persist (onChange, local storage, files) and sync, but are not undoable in v1; deletePage marks its elements isDeleted with newElementWith so collaborators and saves see it. (not recording page operations in the undo stacks (a page add/delete spans two pages' stacks and would need appState deltas for pages)) — Matches the approved assumption 2 and keeps History element-only.
- Add page position (FR-11): addPage inserts the new page right after the active page (fractional key between the active page and its next visible neighbour), names it with getDefaultPageName ("Page N", N = visible page count + 1, incremented until unused) and switches to it. — Mirrors spreadsheet/Figma tab behaviour and keeps the new tab next to the context the person was in.
- File format version (FR-25 ADR): VERSIONS.excalidraw stays 2; the change is additive (appState.pages, appState.activePageId, appState.pageViewports, element.pageId), and today's restore ignores the unknown appState keys and keeps element.pageId by spread. — Older readers load new files (showing all pages overlapped on one canvas) instead of rejecting them; no reader branches on the version today.
- Restoring page state: restoreAppState always derives pages/activePageId/pageViewports from the imported appState via restorePageState and never falls back to the local appState for these three keys; after restore, reassignOrphanedElementsToPage moves elements whose pageId is not a visible page onto the first visible page (file load in blob.ts and App.initializeScene only, never in the collab path). — Loading a legacy file while the browser holds a multi-page drawing must yield exactly one default page (AC-5), and remote elements may legitimately arrive before their page.
- Image export and embedded scene (FR-26 ADR): prepareElementsForExport filters to appState.activePageId when given, so PNG/SVG/clipboard/resave export only the active page; the embedded scene (PNG/SVG metadata) is written with toActivePageExportState(appState): pages reduced to the active page and pageViewports to its entry. — Approved assumption 4: the embedded scene matches the visible export; re-importing an exported image yields a one-page drawing.
- Public getSceneElements semantics: ExcalidrawImperativeAPI.getSceneElements() returns every page's non-deleted elements (scene.getNonDeletedElementsAllPages()); getSceneElementsIncludingDeleted() is unchanged (all pages); the JSON export dialog receives all pages' elements, the image export dialog only the active page's. — Hosts (excalidraw-app collab start, share links, Excalidraw+ export, unload checks) treat it as the whole drawing; returning one page would drop the others when they write it back.
- Collaboration transport (FR-30): SCENE_INIT and SCENE_UPDATE payloads gain an optional `pages: DrawingPage[]` (all records incl. tombstones); a client broadcasts pages whenever getPagesVersion(pages) exceeds its last broadcast/received pages version, and always in INIT and the periodic full sync; receivers merge with reconcilePages and apply via updateScene({appState: {pages}}, NEVER). activePageId and pageViewports are never sent. (not a new WS subtype for pages (two messages per change, and old clients would log an unknown subtype)) — Old clients ignore the extra payload key; pages ride the same encrypted channel as elements.
- Firebase room storage (FR-31): The scenes/{roomId} document keeps sceneVersion/iv/ciphertext (elements array, unchanged) and gains optional pagesIv/pagesCiphertext: the JSON page records encrypted with the room key; saveToFirebase reconciles stored pages with local ones inside the transaction; a document without pages fields loads as null pages, which restore turns into the default page. The cached saved-version is getSceneVersion(elements) + getPagesVersion(pages). — Additive fields: rooms saved before the change load unchanged, and an old client's transaction.update leaves the pages fields in place.
- Tab bar placement and visibility (FR-19 ADR): PagesTabBar renders in the desktop Footer between footer-left and the FooterCenter tunnel, and in the mobile bottom bar above the toolbar island; it renders nothing when zenModeEnabled is true or the host passes UIOptions.pages === false; in view mode it shows the tabs (switching works) but hides the add button, rename, drag and the tab menu. — Approved assumption 3; viewers may switch pages per the role matrix.
- Search across pages (FR-28): handleSearch scans scene.getNonDeletedElementsAllPages(); each SearchMatchItem carries pageId; result rows show the page name when the drawing has more than one visible page; focusing a match on another page first runs actionSwitchPage (source "ui") and the zoom-to-match effect re-runs once activePageId changes. — Search spans the drawing while highlighting and viewport logic stay page-local.
- Library and clipboard page ids (FR-27): Library items and clipboard payloads are left as they are (they may contain a pageId); insertion through addElementsFromPasteOrLibrary always reassigns the active page. — One stamping point is simpler and covers older clipboard/library data too.
- Snapshot churn (NFR-4): Snapshots that hold AppState (contextmenu, history, regressionTests) and the embedded-scene SVG payloads (export.test.tsx, scene/export.test.ts) are regenerated by tooling units running vitest --update on exactly those test files after all code lands; element snapshots do not change because default-page elements carry no pageId. — Approved assumption 5; reviewers check the regenerated diff only adds the page fields.
