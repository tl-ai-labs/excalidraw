## Decisions

- Name and signature of the inverse: export const revertDarkModeFilter = (color: string, enable = true): string, in packages/common/src/colors.ts directly after applyDarkModeFilter, reached through the existing `export * from "./colors"` of @excalidraw/common. (not applyDarkModeFilterInverse; not invertDarkModeFilter (reads as applying an invert filter)) — Mirrors applyDarkModeFilter's signature (same enable flag, same string-in hex-out contract) so call sites read symmetrically.
- Inverse arithmetic: Undo the steps in reverse order: first the existing cssHueRotate(r, g, b, -180 as Degrees) (hue-rotate(180deg) is its own inverse in the CSS matrix), then the exact algebraic inverse of cssInvert at 93%: Math.round(clamp((c - 255 * p) / (1 - 2 * p), 0, 255)) with p = clamp(percent, 0, 100) / 100; alpha copied from the input through rgbToHex like applyDarkModeFilter. (not special-casing black and white; not brute-force preimage search over the RGB cube (too slow on the per-pointermove path); not a precomputed lookup table) — A general closed-form inverse round-trips every colour the forward transform does not clamp, costs one tinycolor parse, and matches the measured values the test pins.
- Caching the inverse: No cache; DARK_MODE_COLORS_CACHE, cssInvert, cssHueRotate and applyDarkModeFilter stay byte-for-byte unchanged. (not a second module-level Map keyed by picked colour) — Picked pixels are arbitrary (images, gradients, antialiasing) so a cache grows without bound, and NFR-1 forbids touching the forward cache.
- Exact match before the inverse: export const matchDarkModeColor = (pickedColor: string, sceneColors: Iterable<string>): string | null in colors.ts directly after revertDarkModeFilter: it returns the first candidate c, scene colours first in iteration order and then the palette (COLOR_PALETTE black, white, then each family's shades in object order; transparent excluded), whose applyDarkModeFilter(c).slice(0, 7) equals pickedColor.toLowerCase().slice(0, 7) (alpha ignored on both sides), returning c verbatim; candidates that are transparent or not a valid colour are skipped; null when nothing matches. getCurrentColor in dark theme returns matchDarkModeColor(color, sceneColors) ?? revertDarkModeFilter(color). (not widening the round-trip tolerance; not a hard-coded table of the 13 clamped colours; not matching inside revertDarkModeFilter (keeps the inverse pure and scene-free)) — The 13 clamped palette colours (yellows among them) cannot be recovered by any inverse; an exact forward match against colours the user can actually have drawn recovers them exactly, and the inverse stays the fallback for arbitrary pixels.
- Scene colours for the match: Built once per eyedropper effect run in EyeDropper.tsx, only in dark theme: a Set<string> of strokeColor and backgroundColor of stableProps.app.scene.getNonDeletedElements(), in element order; not rebuilt per pointermove. (not rebuilding from the scene on every pointermove (O(elements) on the per-move path, NFR-3)) — Keeps the per-move cost to a Set walk of distinct colours plus cached applyDarkModeFilter lookups.
- Where the inverse is applied: Once, inside EyeDropper.tsx getCurrentColor (exact match first, inverse as fallback), when appState.theme === THEME.DARK; every consumer (LayerUI onChange preview, App.openEyeDropper onSelect, ColorInput's eyedropper, App.bucketFill temporary eyedropper and therefore App.cursor's bucket-fill cursor and actionChangeBucketFillBackgroundColor) receives the already-reverted colour, so actionProperties.tsx, App.bucketFill.ts and App.cursor.ts need no edit. (not reverting in each consumer (four call sites, two of them in LayerUI.tsx/App.tsx/ColorInput.tsx outside the allowlist, and a double-revert risk); not reverting in the bucket-fill and cursor code as well (applies the inverse twice, violating FR-5)) — getCurrentColor is the single point where a canvas pixel becomes a colour, so applying the inverse there guarantees exactly-once for every user.
- Eyedropper preview swatch: The preview div keeps `style.background = currentColor` (now the reverted colour); its existing CSS `filter: var(--theme-filter)` re-applies the dark transform, so the swatch shows what the canvas shows. No scss change. — Before the fix the swatch double-transformed the pixel; the fix makes it correct for free.
- Round-trip tolerance and exceptions: ±1 per RGB channel, constant ROUND_TRIP_TOLERANCE = 1, never widened; 13 palette colours whose forward hue-rotate clamps are listed by name and hex with their measured round-trip hex and signed per-channel error (round trip minus original), asserted exactly. — FR-2 / AC-1 fix this shape; the clamped colours are not injective under the forward transform, so no inverse can recover them; the eyedropper recovers them through matchDarkModeColor instead, and the exceptions test stays unchanged.
- Feeding a pixel to the eyedropper in jsdom: After render, vi.spyOn(h.app.canvas.getContext("2d")!, "getImageData") returning `{ data: Uint8ClampedArray.from([r, g, b, 255]) } as unknown as ImageData`; vitest-canvas-mock returns the same context object for the same canvas, which is the one EyeDropper reads. (not drawing on the mock canvas (vitest-canvas-mock always returns zeroed pixels)) — Deterministic pixel value independent of the mock renderer.
- Public API companion: Re-export revertDarkModeFilter from packages/excalidraw/index.tsx in the same import and export statements as applyDarkModeFilter, and add a `### Fixes` entry under `## Unreleased` in packages/excalidraw/CHANGELOG.md. — applyDarkModeFilter is public there, so hosts that use it to render get its inverse alongside; matchDarkModeColor stays internal (exported from @excalidraw/common only, not re-exported from index.tsx).
