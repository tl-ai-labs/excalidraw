## Conventions

- TypeScript strict mode; no `any` in new code; no new dependencies.
- Formatting is Prettier via eslint-plugin-prettier (@excalidraw/prettier-config): 80 columns, double quotes, semicolons, trailing commas, 2-space indent; `eslint --fix` applies it.
- Import order as in EyeDropper.tsx: external packages, then @excalidraw/* value imports, blank line, `import type` lines, blank line, relative imports.
- Internal packages are imported by their aliases (`@excalidraw/common`, `@excalidraw/element`, `@excalidraw/math`), never by relative paths across packages.
- Tests run on Vitest with globals (`describe`, `it`, `expect`, `vi`, `afterEach` are not imported) and jest-style matchers (`toBe`, `toEqual`).
- Editor tests render `<Excalidraw />` through `render` from ./test-utils, seed elements with `API.createElement` + `h.app.updateScene` inside `act`, and read state via `const { h } = window;`.
- Colour hex strings are lowercase, as produced by `rgbToHex`; compare colours as strings with `toBe`.
- Keep comments to one short line where the intent is not obvious; no commented-out code.

## Decisions

- Name and signature of the dark-mode inverse (FR-4): `export const reverseDarkModeFilter = (color: string): string` in packages/common/src/colors.ts, placed right after `applyDarkModeFilter`, re-exported by the existing `export * from "./colors"`; it keeps the input's alpha the way `applyDarkModeFilter` does (6-digit hex when opaque, 8-digit otherwise) and returns an invalid input unchanged. (not invertDarkModeFilter (clashes with the private cssInvert step); not an (r, g, b) number signature (callers hold hex strings)) — Mirrors applyDarkModeFilter's string-in/string-out contract so callers compose the two directly.
- How the inverse finds a pre-image: No search: the 180-degree hue matrix is M = 2W - I (its own inverse), so every output channel is u_i = 2L - v_i with L the luminance of the invert-space point v (integers 18..237); for pixel (r, g, b) the canonical pre-image is vG = Math.round(0.426r + 0.43g + 0.144b), vR = vG + g - r, vB = vG + g - b, each clamped to 18..237; the inverse runs cssHueRotate on that centre, then on its other 26 +/-1 neighbours to absorb floating-point ties at .5, returns the first exact match (else the nearest), and maps v back to light space with a one-time 256-entry cssInvert table. Bound per call: at most 27 cssHueRotate evaluations, zero applyDarkModeFilter calls, no result cache. (not the earlier phase-2 sweep over (vR, vB) for clamped pixels (up to ~145k candidate evaluations per call, breaks NFR-3); not a result cache as the cost bound (a cold call is still unbounded); not closed-form inverse without verification (a .5 tie can flip one rounding); not precomputing a full reverse table (16M forward evaluations)) — Green never clamps and u_i - uG = vG - v_i is an integer, so an unclamped pixel has exactly one pre-image, round(M x pixel); a red or blue channel clamped at 0 or 255 only bounds vG - v_i from one side, and the canonical point sits on that bound, which case by case (one channel high or low, both high, both low; mixed high/low has no pre-image) is a pre-image whenever any exists, so FR-4 holds for every colour at fixed cost.
- Per-move cost bound (NFR-3): Each eyedropper pointermove does one topmost-element hit-test walk, at most 3 applyDarkModeFilter calls (background, stroke, view background) and at most one reverseDarkModeFilter call, which itself does at most 27 cssHueRotate evaluations; none of these counts depends on the colour. (not bounding cost by memoising inverse results (a cache does not bound a cold call)) — NFR-3 caps per-move work at one hit-test, a constant number of filter calls and one constant-cost inverse.
- Where the exact stored colour comes from (FR-1): In dark theme the eyedropper hit-tests the topmost element at the cursor and returns the first stored candidate whose `applyDarkModeFilter` equals the sampled pixel, in this order: that element's backgroundColor, its strokeColor, then `app.state.viewBackgroundColor`; only when none matches does it return `reverseDarkModeFilter(pixel)` (FR-2). (not inverse only (the filter is not injective, so it cannot return the stored hex for colliding colours); not matching against every element in the scene (unbounded per-move cost)) — The scene is the only source that can return the stored value byte for byte, at a constant three filter calls per move.
- Hit test inside EyeDropper: Loop `app.scene.getNonDeletedElements()` from the last index down and take the first element for which `hitElementItself` (from @excalidraw/element) is true, with threshold `element.strokeWidth / 2 + 0.1` and `elementsMap: app.scene.getNonDeletedElementsMap()`. (not App.getElementAtPosition (not on AppClassProperties, and packages/excalidraw/types.ts is outside the allowlist)) — Uses only what `useApp()` exposes and keeps the change inside the frozen allowlist.
- Preview swatch colour (FR-5): The swatch background shows the on-screen pixel colour; `onChange` and `onSelect` receive the picked colour. (not showing the picked (light-theme) colour, which would not match what the user sees under the cursor in dark theme) — The swatch mirrors the canvas the user is looking at; the callbacks carry the value that is stored.
- Theme and coordinates source in the eyedropper: Read `stableProps.app.state` at event time for theme, zoom, scroll and viewBackgroundColor; keep the existing `appState.offsetLeft/offsetTop` pixel read unchanged; the effect's dependency list does not change. (not adding appState.theme to the effect dependencies (re-attaches listeners on theme change for no gain)) — app.state is always current and UIAppState omits zoom and scroll.
- How the eyedropper test controls the sampled pixel: Before pressing `i`, take `const ctx = h.app.canvas.getContext("2d")!`, `vi.spyOn(ctx, "getImageData")` to return `{ data: Uint8ClampedArray.of(r, g, b, 255) } as ImageData`, and `vi.spyOn(h.app.canvas, "getContext").mockReturnValue(ctx)`; restore with `vi.restoreAllMocks()` in afterEach. (not spying CanvasRenderingContext2D.prototype (the canvas mock defines its methods per instance)) — jsdom's canvas mock does not render, and pinning getContext makes the stub hold whether or not the mock caches contexts.
