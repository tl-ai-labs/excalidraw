## Decisions

- ExcalidrawTextElement styled ranges field name and empty representation: Optional field textStyles?: readonly TextRangeStyle[] where TextRangeStyle = Readonly<{ start: number; end: number; color?: string; highlight?: string }>, omitted (undefined / key not set) when empty (not Always setting textStyles: [] on every text element; not Indexing ranges into wrapped element.text instead of element.originalText) — Omitting textStyles when empty keeps unstyled text elements byte-identical in memory and serialized JSON, preserving existing test snapshots and backward compatibility while indexing by UTF-16 code-unit offsets into originalText survives wrapping and resizing.
- Boundary behavior when typing at the end of a styled range: Pure insertions at offset pos where range.start < pos <= range.end extend range.end by insertedLen; pure insertions at pos <= range.start shift both start and end right by insertedLen (not Leaving range.end unchanged when typing at pos === range.end) — Extending on insertion at range.end matches standard rich-text editor behavior where continuing to type at the end of a coloured or highlighted word continues that style.
- Clearing range colour or highlight and resolving overlapping ranges: Applying color === "transparent", null, or equal to element.strokeColor clears color on the selected span while preserving highlight; applying highlight === "transparent" or null clears highlight while preserving color; later ranges override earlier ranges per style attribute and adjacent identical ranges merge (not Storing redundant color entries equal to element.strokeColor or "transparent" in textStyles; not Clearing both color and highlight when only one attribute is reset) — Independent attribute clearing lets users remove highlight without losing text colour (or vice versa) and drops ranges that have neither attribute left.
- Per-line LTR vs bidi/RTL run positioning on Canvas and SVG: Use isRTL(element.text) only for element base direction, and branch run horizontal positioning per visual line on hasRTLChars(line.text): pure-LTR lines (!hasRTLChars(line.text)) use left-prefix getLineWidth measurement, while lines with hasRTLChars(line.text) segment into directional bidi runs, order them visually via UAX#9 level reversal relative to base direction, and accumulate getLineWidth across visual runs (not Branching run positioning on element-level isRTL(element.text) alone; not Relying solely on DOM Range.getBoundingClientRect() which returns zero widths in jsdom/non-DOM environments) — An LTR-first line containing RTL tokens has isRTL(element.text) === false but hasRTLChars(line.text) === true; per-line hasRTLChars detection with UAX#9 visual-order width accumulation produces accurate run x/width on both browser canvas and SVG export as well as Vitest/jsdom.
- WYSIWYG live preview of styled ranges and selection preservation across properties panel clicks: Render a synchronized mirror div (.excalidraw-wysiwyg-preview) behind the textarea with styled <span> runs while setting textarea color/-webkit-text-fill-color to transparent and caretColor to the dark-mode-filtered strokeColor when textStyles is non-empty, and cache the textarea selection range so clicking Stroke or Highlight pickers applies to the selected substring and restores the selection (not Replacing the textarea with a contentEditable div; not Only showing styled ranges after exiting the text editor) — Keeping the native textarea preserves all existing keyboard, IME, paste, list-marker, and test interactions while the synchronized mirror layer displays per-range colour and highlight live during editing.
- Highlight colour picker popup id isolation and sticky-note ink sync: Add "textHighlight" to AppState["openPopup"] in types.ts, map openPopup: "elementBackground" from ColorPicker's updateData to "textHighlight" in actionChangeTextHighlight.perform, and in actionChangeTextHighlight.PanelComponent pass ColorPicker an appState view that maps "textHighlight" <-> "elementBackground" (and maps a real "elementBackground" to "canvasBackground" so ColorPicker sees openPopup !== type), while in actionChangeStrokeColor bypassing element.strokeColor, currentItemStrokeColor, and syncStickyNoteInk when editingTextElement has a non-empty selection (start < end) (not Sharing appState.openPopup === "elementBackground" between actionChangeBackgroundColor and actionChangeTextHighlight; not Withholding actionChangeBackgroundColor while editing a sticky-note label (which breaks sticky-note background editing during label edit); not Using component-local useState for popup state without updating appState.openPopup) — ColorPicker.tsx (not on the allowlist) opens when appState.openPopup === type and accepts only ColorPickerType values; storing "textHighlight" in AppState["openPopup"] and translating at actionChangeTextHighlight's boundary lets both the sticky-note background picker and the text highlight picker render simultaneously with distinct popup ids so opening one never opens the other.

### U02 — create `packages/element/src/textStyles.ts` (codegen)

Behaviour: Provide pure helpers to normalize, apply, query, shift, segment, and project UTF-16 character range styles onto wrapped visual lines with LTR and bidi/RTL run positioning.

Rules:
1. 1. Export types TextStyleSegment = Readonly<{ text: string; start: number; end: number; color?: string; highlight?: string }>, LineTextRun = Readonly<{ text: string; start: number; end: number; color?: string; highlight?: string; x: number; width: number; direction: "ltr" | "rtl" }>, and WrappedLineWithRuns = Readonly<{ line: WrappedTextLine; runs: readonly LineTextRun[] }>.
2. 2. normalizeTextRanges(ranges, textLength, baseStrokeColor?): if !Array.isArray(ranges) or textLength <= 0 return undefined; collect valid entries where start and end are finite numbers, floor and clamp both to [0, textLength], ignore entries with start >= end; sanitize color and highlight as non-empty trimmed strings excluding "transparent" (and clear color if baseStrokeColor is provided and color.toLowerCase() === baseStrokeColor.toLowerCase()); strip unknown keys; split at all boundary points so later input entries override earlier entries per attribute (color and highlight independently, where a later entry only overrides the attributes it specifies), drop segments with neither color nor highlight, merge adjacent segments with identical color and highlight, and return undefined when the result is empty.
3. 3. applyTextRangeStyle(ranges, textLength, selection, style, baseStrokeColor?): clamp selection.start and selection.end to [0, textLength]; if start >= end return normalizeTextRanges(ranges, textLength, baseStrokeColor); partition [0, textLength] at all existing range boundaries plus selection.start and selection.end; on intervals inside [selection.start, selection.end], if style.color !== undefined set color to undefined when style.color === null || style.color === "" || style.color === "transparent" || (baseStrokeColor !== undefined && style.color.toLowerCase() === baseStrokeColor.toLowerCase()) else style.color while preserving existing highlight, and if style.highlight !== undefined set highlight to undefined when style.highlight === null || style.highlight === "" || style.highlight === "transparent" else style.highlight while preserving existing color; normalize and merge adjacent identical intervals and return undefined if empty.
4. 4. getUniformTextRangeStyle(ranges, start, end, key): for a non-empty selection [start, end], return the string value of key ("color" | "highlight") if and only if every code unit in [start, end) is covered by ranges with the exact same non-empty value for key; otherwise return null.
5. 5. shiftTextRangesAtOffset(ranges, offset, deletedLength, insertedLength, nextTextLength): if !ranges?.length return undefined; for pure insertion (deletedLength === 0 && insertedLength > 0), ranges with start >= offset shift both start and end by +insertedLength, ranges with start < offset && offset <= end (strictly containing offset or ending at offset) keep start and extend end by +insertedLength, and ranges with end < offset are unchanged; for deletion or replacement (deletedLength > 0), first apply deletion of [offset, offset + deletedLength) by mapping any boundary x <= offset to x, x >= offset + deletedLength to x - deletedLength, and offset < x < offset + deletedLength to offset (dropping ranges that collapse to start >= end unless the original range strictly enclosed [offset, offset + deletedLength) and insertedLength > 0), then if insertedLength > 0 apply the pure insertion rule at offset (extending ranges where start < offset && offset <= end and shifting ranges where start >= offset by +insertedLength); finally normalize with normalizeTextRanges(result, nextTextLength).
6. 6. shiftTextRanges(ranges, prevText, nextText): if !ranges?.length return undefined; normalize line endings of prevText and nextText with .replace(/\r\n?/g, "\n"); if prevText === nextText return normalizeTextRanges(ranges, nextText.length); compute common prefix length prefixLen and common suffix length suffixLen (with prefixLen + suffixLen <= Math.min(prevText.length, nextText.length)), derive deletedLength = prevText.length - prefixLen - suffixLen and insertedLength = nextText.length - prefixLen - suffixLen, and delegate to shiftTextRangesAtOffset(ranges, prefixLen, deletedLength, insertedLength, nextText.length).
7. 7. splitTextIntoStyledSegments(text, ranges, offset = 0): partition text (representing originalText slice [offset, offset + text.length)) into contiguous non-empty TextStyleSegment items with local start/end offsets in [0, text.length] and any active color/highlight from ranges; when text is empty return a single empty segment [{ text: "", start: 0, end: 0 }].
8. 8. getLineTextRuns(line, ranges, opts): split line.text into logical styled segments using line.start; compute full lineWidth = getLineWidth(line.text, opts.font, opts.renderEnvironment) and lineLeftX = opts.textAlign === "center" ? (opts.elementWidth - lineWidth) / 2 : opts.textAlign === "right" ? opts.elementWidth - lineWidth : 0; when !hasRTLChars(line.text), measure each logical segment's x = lineLeftX + getLineWidth(line.text.slice(0, seg.start), opts.font, opts.renderEnvironment) and width = getLineWidth(seg.text, opts.font, opts.renderEnvironment) with direction: "ltr"; when hasRTLChars(line.text) is true, further split logical segments at directional bidi boundaries (grouping RTL script chars and Arabic-Indic digits \u0660-\u0669\u06F0-\u06F9 as RTL tokens, Latin/ASCII digits/LTR chars as LTR tokens, and resolving neutral whitespace to the surrounding or opts.baseDirection direction), assign UAX#9 embedding levels (base level 0 for baseDirection === "ltr" with RTL runs at level 1, or base level 1 for baseDirection === "rtl" with LTR runs at level 2), order runs visually via UAX#9 level reversal from highest level down to 1, accumulate visual x = lineLeftX + sumOfPrecedingVisualRunWidths using getLineWidth(run.text, opts.font, opts.renderEnvironment), and return the runs in logical order with their computed visual x, width, and direction.
9. 9. projectTextRangesOntoLines(originalText, ranges, opts): obtain WrappedTextLine[] either by matching opts.wrappedText lines sequentially against normalized originalText (skipping soft-wrap spaces and hard newlines so each visual line has exact [start, end] offsets into originalText) when opts.wrappedText !== undefined, or by calling getWrappedTextLines(originalText, opts.font, opts.maxWidth, opts.renderEnvironment); map each WrappedTextLine to { line, runs: getLineTextRuns(line, ranges, opts) }.
